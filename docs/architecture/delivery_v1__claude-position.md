## Линза, через которую я отвечаю

Юра дал явный фильтр: **«думать не что можно классно сделать, а что это даст мне».**
Поэтому каждый пункт ниже привязан к **сценарию из его реальной жизни**, а не к технологической красоте. Если сценарий не звучит — гипотеза отбраковывается, даже если она «modern и scalable».

## TL;DR моей позиции

1. **Корень проблемы — не архитектура, а sync.** Текущий стек (YAML → static + GitHub Pages) под этот use case подходит. Болит **дисциплина связывания** (ручной `llms.txt`, hardcoded `26`, забытый `garden-pesticides.yaml` в `build.py`). Это лечится за неделю.
   *Что даст Юре:* «когда AI или сайт говорит мне про мою коллекцию — это всегда **актуальное** состояние, а не вчерашнее».

2. **Native Android — нет.** Single dev + single user + цикл публикации в Play Store + поддержка отдельного стека = негативный ROI. Никакая фича native (камера, NFC, виджет) не оправдывает входной цены для **этой** задачи.
   *Что НЕ даст Юре:* ничего такого, чего нельзя получить через PWA + AI за 1/10 усилий.

3. **PWA — да, и она уже почти есть.** В `static/manifest.json` и `static/service-worker.js` инфраструктура готова: standalone display, иконки, shortcuts на каталог/диагностику/миксер, оффлайн-кэш. Не хватает: убедиться что SW реально регистрируется в HTML и протестировать установку на твой Android.
   *Что даст Юре:* иконка «Plants Care» на главном экране Android. Один тап у растения → каталог открыт. Без интернета. Без открывания браузера.

4. **Самый сильный апгрейд UX — H9 (личный AI-app со фото и журналом).** Ты сам это назвал и отшутился «перебор». **Это не перебор.** В 2026 это бесплатно реализуется поверх PWA: `<input type="file" capture="camera">` + Claude/Gemini Vision API + запись события в YAML через тот же git-flow.
   *Что даст Юре:*
   - сфотографировал лист с белым пушком → AI распознал червеца → сразу подтянул протокол из твоей `garden-pesticides.yaml` → предложил «записать событие»
   - тапнул «да» → в `data/events/alocasia_regal_shields.yaml` записалось `2026-05-06 mealybug Confidor drench`
   - через месяц при следующей проблеме AI видит **твою историю** этого конкретного растения, а не общие советы
   - это и есть «помощник», а не «справочник»

5. **Чат-интерфейс — через те же CLI которые ты только что вызвал** (`codex` / `gemini` / меня). Не строить отдельного бота. Если очень хочется в браузере — простой overlay в PWA, который шлёт в твой Gemini API ключ запросы по `api/*.json`.
   *Что даст Юре:* быстрый ответ «что мешать в канистру B» без листания сайта.

6. **Продукт для других — преждевременно.** Твой workflow уникальный (жёсткий RO+ATAMI, твои PPM-группы, твой каталог VGI). Как «app for plant care» он не упакуется. Если когда-то — это **другой** проект, не этот.
   *Что даст Юре, если игнорировать сейчас:* свободу делать ровно то, что **тебе** нужно, без оглядки на абстрактного «другого пользователя».

## План на первую неделю (5–7 часов работы)

| # | Задача | Время | Эффект |
|---|---|---|---|
| 1 | В `build.py` подключить `garden-pesticides.yaml` (как уже сделано для `garden-fertilizers.yaml`) | 10 мин | Confidor/Nimbi/Biomectin появляются на сайте и в `api/` |
| 2 | Заменить hardcoded `'All 26 plants'` на `len(b.plants)` | 5 мин | Больше нет ручного счётчика |
| 3 | Написать `scripts/build_llms.py`, который собирает `llms.txt` из YAML+MD автоматом | 3–4 часа | `llms.txt` всегда совпадает с YAML |
| 4 | Подключить регистрацию `service-worker.js` в `templates/base.html` (если ещё нет), пересобрать, поставить PWA на твой Android | 1 час | «Иконка на главном экране» → доступ за 1 тап, оффлайн |
| 5 | В `CLAUDE.md` короткий блок «куда что класть» (факт → YAML, нарратив → docs/, никогда руками в `llms.txt`) | 20 мин | Дисциплина зафиксирована — больше не разойдётся |

## Что бы я НЕ делал прямо сейчас

- **Native Android.** Только если через 3 месяца PWA реально не зашла.
- **Capacitor / Flutter / React Native.** Преждевременная универсальность.
- **Telegram/WhatsApp бот.** Ещё один канал = ещё один источник рассинхрона.
- **Notion / Airtable как primary store.** Vendor lock + теряешь git-историю + теряешь машинообработку.
- **Переписывать `build.py` на новый фреймворк.** Он работает. Чинится в нескольких местах.
- **Закладывать multi-tenant** (несколько пользователей с разными коллекциями). Это превращает проект в SaaS — другая работа, другие риски.

## Где я могу ошибаться (честно)

1. **PWA на Android может не дать ощущения «нативности».** Если для тебя критично что иконка ведёт себя ровно как app — может быть Capacitor-обёртка реально нужна. Это вопрос на неделю эксперимента, не на месяц переписывания.

2. **AI-ввод через CLI** может быть медленнее чем «открыл YAML и допечатал». Но он снимает порог «не хочу сейчас лезть в код» когда стоишь в саду.

3. **«Продукт для других» я отсекаю слишком уверенно.** Возможно есть ниша (узкое сообщество aroid-коллекционеров на RO), но это другой разговор и точно не сейчас.

## Stop-loss (когда понять что я ошибся)

- Через **месяц** после H1+H2: ты по-прежнему открываешь YAML руками, а не PWA на телефоне в момент работы → значит проблема не в доступе, а в воркфлоу. Переходить к H7 (чат-overlay).
- Через **3 месяца**: ты по-прежнему не «достаёшь телефон у канистры» → проблема глубже, форма доставки не та. Тогда честно смотреть на native или чат-бот.
