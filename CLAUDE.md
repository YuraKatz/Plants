# Plants Project — Onboarding для Claude

База знаний для AI-помощника по уходу за коллекцией комнатных растений Юрия Каца (Кацрин, Голан, Израиль).

## Контекст пользователя

- **Кто:** Юрий Кац, Кацрин
- **Коллекция:** 33 комнатных растения (см. `data/plants.yaml`). Балконных и уличных НЕТ.
- **Планы:** скоро добавит категорию садовых деревьев — отделять от комнатных, не смешивать рекомендации.
  - **Источник для садовой категории:** `C:/Dev/Personal/MyCentral/garden.yaml` (отдельный репо MyCentral). Там уже зафиксировано: деревья (авокадо, манго, хурма, цитрус, нектарин, персик, виноград), вермикомпост ~0.5 ведра/нед, базовые удобрения (NPK 17-10-27, worm_tea), цели (storage fertilizer kit, баланс органика/минералы, мониторинг отклика деревьев). Перед добавлением tree-категории — синхронизироваться с этим файлом, не выдумывать состав сада с нуля.
- **Цель проекта:** knowledge base для AI-помощника + публичный статический сайт.

## Архитектура проекта

- **Источник истины:** YAML-файлы в `data/`. Сайт **генерируется** из них.
- **Билд:** `python scripts/build.py` → пишет HTML в `site/`.
- **Темплейты:** Jinja2 в `templates/` (страницы в `templates/pages/`).
- **Стили/скрипты:** `templates/css/`, `templates/js/`, статика в `static/`.
- **i18n:** `data/i18n/{ru,en,he}.yaml` — три языка.
- **Деплой:** автоматически на GitHub Pages при push в `main`/`master` (см. `.github/workflows/`). Деплоит папку `site/` в ветку `gh-pages`.
- **Локальный запуск/проверка:** запустить `python scripts/build.py` после изменений и открыть `site/index.html`.

### Что важно при редактировании `data/`

- Любая правка YAML напрямую попадает на публичный сайт после push.
- Перед коммитом — прогнать `python scripts/build.py` локально, проверить что страницы собираются.
- Если добавляешь новые поля в YAML и хочешь чтобы они появились на сайте — нужно обновить **и** темплейты в `templates/`.
- Новые поля для AI-контекста (например `indoor_use`, `my_opinion`, `collection_targets` в `fertilizers.yaml`) сейчас **не** рендерятся — они нужны только для Claude. Это нормально, но имей в виду: они увеличивают размер YAML и могут попасть в `llms.txt` если он генерируется из data.

## Правила работы с данными

### 1. Только подтверждённые источники
- Состав, дозировки, pH продуктов — **только из официального источника** (сайт производителя, этикетка, инструкция).
- Если данных нет — **спроси**, не выдумывай и не экстраполируй "по аналогии с похожими".
- При добавлении продукта в `fertilizers.yaml` — указывай поле `source:` с URL.

### 2. Не раздувать
- При добавлении нового материала — спроси "что именно сохранить", а не сразу пиши анализ на полстраницы.
- Не создавай записи для продуктов, которых **нет у Юры**.
- Не добавляй секции "по аналогии" или "также может быть полезно" без явной просьбы.

### 3. Что НЕ хранить
- **Цены, размеры упаковок, доставка** — устаревает, для AI бесполезно.
- **Чеки покупок и даты** — это не входит в knowledge base.
- **Маркетинговые обещания** производителя без подтверждённого механизма действия.

### 4. Перед рекомендациями
- Сверяй растение с **PPM-группой** в `water-requirements.yaml`.
- Сверяй продукт с уже **существующими аналогами** в `fertilizers.yaml`.
- Учитывай **запреты** (например, dionaea — никаких удобрений; nephrolepis — чувствителен к маслам).

### 5. Когда мнение запрашивается явно
- Юра иногда просит **твоё мнение**, не пересказ источника.
- В этом случае — давать честную оценку, **сравнивать с тем, что уже есть в каталоге**, отмечать дублирование.
- Чётко разделять: "сайт пишет X" vs "моя оценка Y".

## Структура `additives` в `fertilizers.yaml`

Для каждого продукта VGI:
- `name`, `local_name` (иврит), `brand`, `source` (URL)
- `composition` — точные проценты
- `application` — дозировки и методы
- `indoor_use` — оценка для коллекции Юры с явным разделением "сайт говорит" vs "моя экстраполяция"
- `collection_targets` — конкретные растения из коллекции, для которых продукт реально полезен

**Не добавлять:** `price`, `currency`, `sizes`, `shipping`, `pricing_tiers`, `purchased_price`.

## Язык

- Общение и записи — **на русском**.
- Названия продуктов на иврите дублировать в `local_name`.
- Имена растений в `plants.yaml` — на русском (привычные названия).

## Типичные ошибки прошлых сессий (избегать)

1. **Выдумывание состава** продукта вместо запроса источника.
2. **Создание записей для продуктов, которых нет** в покупках Юры.
3. **Игнорирование RO-протокола** при анализе (например, рассуждения про "жёсткую воду Голан").
4. **Дублирование функционала** — добавление продукта без сравнения с существующими в каталоге.
5. **Хранение цен и чеков** в knowledge base.
6. **Раздутые секции "может быть полезно"** без конкретной привязки к коллекции.

## Когда возникает вопрос — спросить

Если в чате нет данных для рекомендации — **спроси**, не пиши "обычно делают так". Юра использует базу для своей коллекции, а не для усреднённого пользователя.
